# 群晖部署指南 · 0.1.0

目标：用户提供的 DS423+ / x86_64、DSM 7.4.1、Container Manager 24.0。开发环境未连接该 NAS，菜单名称以实际 DSM 页面为准。

## 外网与文件交换

通过工作台 HTTPS 上传简历/JD、下载报告。人工跟进表下载到电脑，在 Excel 编辑后上传回传；数据保存在 NAS，不需要互联网 SMB、WebDAV 或同步盘。若未来需要频繁操作大量文件，可另行使用公司已有 VPN。

HTTPS 需要域名、有效证书和可达的反向代理。运营商 CGNAT 环境下，仅配置路由器映射不能解决可达性，需另外确认接入方案。本项目不自动开通公网或隧道。

## 准备项目

推荐路径 `/volume1/docker/hr-assist`。可从 GitHub 下载源码压缩包并解压，也可使用 Git：

```sh
git clone https://github.com/wyf518www/HR_Assist.git /volume1/docker/hr-assist
cd /volume1/docker/hr-assist
mkdir -p storage/state storage/data secrets
cp .env.example .env
```

编辑 `.env`：

```dotenv
HR_PUBLIC_URL=https://hr.你的域名
HR_ADMIN_USERNAME=admin
HR_PORT=8088
HR_UID=10001
HR_GID=10001
HR_STORAGE_ROOT=/volume1/docker/hr-assist/storage
```

`HR_PUBLIC_URL` 必须与浏览器访问地址的协议、域名、非标准端口完全一致，不含结尾 `/` 或子路径。只支持独立域名根路径。

在 `secrets/admin_password.txt` 中填入至少12位强密码，仅一行。用密码管理器保存，勿用示例文字。NAS 如已安装 OpenSSL，可生成随机密码文件：

```sh
openssl rand -base64 36 > secrets/admin_password.txt
sudo chown -R 10001:10001 storage secrets
sudo chmod 700 storage secrets
sudo chmod 600 secrets/admin_password.txt
```

上述权限操作仅针对**新建项目内的 storage、secrets**，不要用于其他共享目录。若使用现有专用账户 ID，同步修改 `.env` 和目录所有者；DSM ACL 也须允许读写数据目录、读取密码文件。不要通过设置777解决问题。

首次启动将密码存为 PBKDF2 哈希。重启不会用密码文件覆盖已有管理员。邮箱和模型密钥使用 `storage/state/secrets.key` 加密保存。

## 构建与启动

在 Container Manager 创建项目，选择源码目录并使用现有 `docker-compose.yml`，构建后启动。首次构建需可访问 Docker Hub、Debian 仓库和 Python 包源。

有 SSH 权限也可执行：

```sh
cd /volume1/docker/hr-assist
sudo docker compose config --quiet
sudo docker compose build
sudo docker compose up -d
sudo docker compose ps
curl -fsS http://127.0.0.1:8088/healthz
```

健康检查应返回 `status: ok`。应用只绑定 NAS 的 `127.0.0.1:8088`，电脑不能直接访问该端口，需走反向代理。

镜像为 `linux/amd64`、单 worker、非 root、只读根文件系统，限制2GB内存、2 CPU、256MB临时空间。DS423+ 同时运行其他服务时需检查可用内存。资源不足将导致解析失败并保留原件。

## 配置 HTTPS 反向代理

在 DSM 的登录门户 / 高级 / 反向代理中新增规则（以实际菜单为准）：

| 设置 | 值 |
| --- | --- |
| 来源协议、主机 | HTTPS，与 `HR_PUBLIC_URL` 一致的域名 |
| 来源端口 | 443，或在 `HR_PUBLIC_URL` 明确填写的端口 |
| 目标 | HTTP，127.0.0.1，8088（或 `HR_PORT`） |
| 证书 | 分配该域名的有效证书 |

若可配置上传限制，设为至少21MB、建议25MB；应用单文件限制20MB。代理读取超时建议240秒，供首次 JD/OCR 解析使用。无需 WebSocket。仅放行 HTTPS，不暴露8000/8088、数据库或共享目录。

应用不信任客户端 `X-Forwarded-*`；登录限流按代理地址合并计算，10次/10分钟。会话8小时，Cookie 为 Secure / HttpOnly / SameSite=Strict。

## 首次配置与试运行

1. 打开 HTTPS 工作台并登录。失败先核对证书、地址与 `HR_PUBLIC_URL`。
2. “岗位与 JD”上传原文并确认七类要求。不限制的条件填写“不限”；不完整或未确认的 JD 不评分。
3. “连接与设置”填写 QQ 邮箱和 IMAP 授权码（不是网页登录密码），启用收件。默认主题同时包含“【BOSS直聘】”和“应聘”，也可选择任一。
4. 填写公司批准的 HTTPS 完整模型接口、模型名称、密钥和批准记录。接口需支持 `messages`、`response_format: json_object`、`choices[0].message.content`；厂商兼容性需实测。
5. 输入已核验的985/211院校名单与来源并确认学历策略。无名单的非销售本科转待核验；不要把不完整名单当成完整名单。硕士放宽院校要求由开关控制。
6. 上传获准使用的测试简历，点击“解析与评估”，核对证据与评分；扫描件关键文字先对照原件人工核验。
7. 下载人工跟进表、填写五个人工字段、上传回传，再下载总览。验证后才启用北京时间每日09:00。

批准记录应覆盖模型供应商的数据留存和不训练条款。软件会移除常见姓名、手机号、邮箱和证件号，不上传 PDF/照片，但经历文字仍可能识别人，去标识化不是匿名化。不要在日志填密钥，不要提交 `.env`、`storage/`、`secrets/`。

## 文件与恢复

| 路径 | 内容 |
| --- | --- |
| `storage/state/hr-assist.db` | 岗位、评估、人工字段、邮件游标、任务、通知 |
| `storage/state/secrets.key` | 凭据加密密钥，丢失后无法解密原凭据 |
| `storage/state/logs/` | JSONL处理日志，不含简历正文和密钥 |
| `storage/data/temporary/` | 不可变简历原件，用于去重和重试 |
| `storage/data/resumes/岗位名/` | 岗位归档副本，哈希校验一致 |
| `storage/data/quarantine/` | 解析异常原件副本 |
| `storage/data/jd/` | JD 原件 |
| `storage/data/followup/` | 人工表导出和成功导入原文件 |
| `storage/data/reports/` | 独立版本总览和岗位报告 |

人工表删行不删除服务器记录；主动清空人工单元格会作为修改合并。记录ID、表头、隐藏元数据不可改。日期、值、公式与数字格式保留；服务器不求值。总览公式的跨表/相对引用不保证与原表等义，五个人工字段建议填写值。字体、边框、批注不作为业务字段同步，上传原文件另行保留。

模型断连或报告写入失败不会推进成功游标。继续任务会复用完成步骤；永久解析失败的项独立保留，批次可完成并列明异常。解决原件问题后可重新上传/继续处理。

每天按北京时间触发；当日恢复服务且已过时间时补触发一次。失败批次手动重试。计划默认关闭，不逐日重演停机期间的任务；通知仅在工作台内显示。

## 备份、升级、密码重置

初期采用停机一致性备份：停止容器，同时备份整个 `storage/`、`secrets/`、`.env` 和源码提交号，再启动。不要只复制运行中的 SQLite 主文件。备份目的地应限制访问并加密。

```sh
sudo docker compose stop
# 在此通过 NAS 备份工具完成一致性备份。
sudo docker compose start
```

恢复时恢复整套目录，核对UID/GID后启动。升级前备份，再拉取代码、构建、启动。第一版没有自动数据库降级；回退使用匹配版本的整套备份。

忘记密码时停止服务，更新 `secrets/admin_password.txt` 后离线重置。所有会话会失效：

```sh
sudo docker compose stop
sudo docker compose run --rm --no-deps hr-assist python -m hr_assist.admin
sudo docker compose up -d
```

不要通过删数据库重置密码。第一版无自动数据清理和个人信息删除界面，保留周期由管理员在备份策略中管理。
