# HR 自动化工作台：招聘流程自动化助手

版本：v0.2，2026-10-23。用途：产品评审与开发基线。本文描述目标软件；当前交付是设计文档和交互原型。

## 1. 产品定义与第一期边界

建立一套运行在 Windows 本机的 HR 工作台。第一期把“收到简历 → 归档 → 依据 JD 评估 → 推荐报表 → 人工跟进 → 反馈校准”串成可恢复、可审计的流程。

用户每天主要完成三件事：处理待确认项、核对推荐依据、继续在 Excel 填写招聘进展。常规收集和报表整理由程序完成，语义理解交给大模型，录用和淘汰决定由人完成。

工作台长期可承载其他 HR 模块，但第一期只交付招聘。入职、考勤、薪酬、绩效、员工管理和对外沟通均不纳入本期。

### 1.1 已经确认的选择

| 决策 | 已确认方案 | 对实现的影响 |
|---|---|---|
| 部署 | Windows 本机、单用户 | 数据和附件存本机；界面默认仅监听 127.0.0.1 |
| 模型 | 可用公司批准的云端接口 | 需配置经批准的提供商；发送前去标识化；本机保留原件 |
| 人工跟进 | 五字段继续在 Excel 填写 | Excel 为这五字段唯一权威来源；界面只读展示 |
| 默认运行 | 北京时间每天 09:00 | 软件调度能力，部署配置完成后才启用；本次不创建实际定时任务 |

### 1.2 原始配置

| 项目 | 初始值 |
|---|---|
| 邮箱 | 部署时填写 QQ 邮箱 |
| 简历根目录 | `D:\workbuddy\简历提取` |
| JD 目录 | `D:\workbuddy\简历提取\岗位JD` |
| 推荐目录 | `D:\workbuddy\简历提取\推荐` |
| 日志目录 | `D:\workbuddy\简历提取\日志` |
| 总览报表 | `D:\workbuddy\简历提取\推荐\招聘推荐总览.xlsx` |

目录仅作为待配置值；不能假设已存在、可写或已被授权给任意服务账号。开发代码位于 `F:\HR_Assist`，与招聘业务数据分开。

## 2. 需求拆解与程序 / 模型分工

| 能力 | 程序负责 | 模型负责 | 人工确认点 |
|---|---|---|---|
| 邮件获取 | IMAP 连接、时间窗口、主题过滤、只读下载 | 无 | 首次连接和授权码配置 |
| PDF 处理 | 类型检查、文件哈希、文本提取、OCR、页码定位 | 在可读文本中识别字段 | OCR 关键字段不确定时复核 |
| 岗位分类 | 按文件名规则解析、映射已登记岗位 | 可提出解释，不直接归档 | 无法识别、名称冲突时选岗位 |
| JD 处理 | 格式解析、版本、必填校验 | 抽取职责、硬条件、技能和证据 | 批准结构化 JD 与评分细则 |
| 候选人分析 | 规则匹配、工作时长计算、分数汇总、等级封顶 | 提取事实、逐项比较、生成有出处的优势和风险 | 核验不确定项、做招聘决定 |
| 报表 | 幂等追加 / 更新、保护五字段、排序、锁检测、备份 | 生成有证据的岗位推荐说明 | 在 Excel 填跟进信息 |
| 持续优化 | 收集反馈、计算指标、版本比较 | 归纳有证据的失配原因、提出草案 | 审核、启用、回滚规则 |
| 定时与通知 | 锁、防重入、断点恢复、统计、站内与 Windows 通知 | 无 | 解决异常 |

不让模型直接操作邮箱、执行附件中的指令、写任意文件或修改 Excel。模型输出先进入结构化校验层，再由业务程序决定可执行动作。

## 3. 用户流程与页面

### 3.0 人事工作台首页与功能选择

软件默认先进入人事工作台首页，再选择业务模块。层级为：**人事工作台 → 招聘流程助手 → 工作概览 / 候选人库 / 岗位与 JD / 报表与反馈 / 运行记录 / 连接与设置**。

- 首页展示功能说明、可用状态、进入入口及已接入模块的待办摘要；当前只有招聘原型可进入。
- 员工档案、入转调离、考勤与休假、薪酬与社保、绩效与培训作为待确认的后续方向，标记“待规划”，不提供可执行入口，不纳入本期开发承诺。
- 进入招聘后切换为该模块内部导航，保留“工作台首页”及品牌返回入口；面包屑同时标识平台、模块和当前页面。
- 默认首次打开是首页，已有招聘深链接仍直接进入对应页面；模块切换不重置当前页面会话中的筛选和人工反馈演示。
- 业务配置属于模块，未来公共连接、通知、任务调度和审计可由平台统一管理。第一期不把尚未实现的全局设置包装成可用能力。

### 3.1 首次配置向导

1. 确认业务数据根目录，检查 JD 与报告目录及可用空间；对需创建的路径展示清单。
2. 输入 QQ 邮箱 IMAP 授权码，保存到 Windows 凭据保护设施；配置文件不存明文密码。按当前邮箱官方配置核验服务器后，测试只读连接。
3. 导入岗位清单及 JD，指定哪些岗位属于销售，确认岗位别名及评分细则。
4. 选择公司批准的云端模型，配置地址、模型标识、凭据引用、批准记录、预算与数据处理限制。先用不含个人信息的样本验证接口。
5. 指定或创建总览工作簿，核对表头；已有报表先备份并完成稳定 ID 迁移预览。
6. 运行一次手动试处理，显示邮件窗口、下载数量、评估依据和报告合并预览。
7. 用户确认试运行结果后，启用每天 09:00 的任务；配置数据保留策略。

### 3.2 工作概览

- 显示最近批次状态、处理区间、下一次计划时间及运行条件。
- 同时显示扫描邮件、主题命中邮件、新附件、成功解析、归档、重复、待分类、待 JD、解析异常数量，避免把这些数量混为一谈。
- 待办按影响排序：全局配置错误、写表冲突、缺 JD、岗位待确认、学历待核验、解析失败。
- “立即执行”“重试失败项”“查看报告”分别进入运行、重试队列和报告页面。
- 手动与定时触发共用同一互斥机制。

### 3.3 候选人库

- 可按岗位、推荐日期、建议等级、人工状态、异常类型筛选。
- 一条列表记录代表一次岗位申请。同一人投多个岗位分别保留，不按姓名合并。
- 详情显示原始文件、来源邮件、文件指纹、JD 版本、规则版本、模型版本及解析时间。
- “评估依据”展示每项 JD 要求、简历原文、页码 / 文本位置、是否满足、得分、缺失信息。
- 将“证据状态”“匹配分”“建议等级”“人工招聘状态”分开展示。
- 五个人工字段在此只读，提示“在 Excel 中维护，点击同步读取最新值”。

### 3.4 岗位与 JD

- 岗位名称、别名、销售标志、是否招聘中、当前 JD 版本、校验状态。
- JD 原文与结构化要求对照展示；模型提取后由用户确认才生效。
- 修改 JD 生成新版本，历史评估仍引用当时版本。
- 对历史简历重新评估要显式发起；新旧评估并存，人工跟进字段不受影响。

### 3.5 推荐报告与反馈

- 总览报表路径、最近成功写入、尚未写入条数、Excel 同步状态。
- 五字段的同步预览显示原值、新值、来源工作簿及时间。
- 反馈区按岗位和版本展示可用反馈样本数、部门筛选通过率、面试评价摘要和未知反馈比例。
- 规则草案显示修改项、证据、影响对象、历史回放结果和回滚入口。

### 3.6 运行记录与设置

- 运行记录按批次展开到邮件、附件及处理阶段，提供有明确目标的重试入口。
- 日志可按成功、失败、跳过、重复、待定、待人工筛选；业务“待定”与技术错误分开。
- 设置包括路径、邮箱、模型、计划、预算、通知、数据保留、备份和恢复。
- 未来 HR 模块通过首页入口扩展；未开发模块仅展示规划状态，不提供不可用的业务操作。

## 4. 日常运行流程

```text
固定本次截止时间并获取任务锁
  → 读取配置、上次成功游标和待重试记录
  → 检查目录、JD 注册表、磁盘、模型和报表结构
  → 连接 INBOX，抓取窗口内邮件元信息
  → 主题过滤 → 下载 PDF 到临时区 → 校验与去重
  → 文本提取 → 必要时 OCR → 证据索引
  → 文件名岗位解析 → 原件归档 / 待分类
  → JD 完整性检查 → 脱敏 → 模型理解 → 输出校验
  → 程序评分、硬条件封顶、记录评估版本
  → 生成岗位报告 → 合并 Excel → 原子提交报告
  → 写运行结果、提交成功游标 → 本机通知
```

### 4.1 时间窗口与幂等

- 时区固定 `Asia/Shanghai`，内部时间用带时区时间或 UTC。UI 展示北京时间。
- 以服务端接收时间为准，不用邮件作者可自行填写的 Date 头。窗口为 `[上次成功截止时间, 本次开始时固定的截止时间)`；首次为截止时间之前 24 小时。
- IMAP 日期筛选可能只有日粒度：先扩大检索范围，再按实际接收时间精确过滤。边界重复由去重消除。
- 同时保存文件夹 `UIDVALIDITY` 和 UID；用于发现游标回退、UID 重建及迟出现的邮件。不能单靠 Message-ID 或未读标记判断是否处理。
- 处理期间到达的新邮件进入下次窗口。中途崩溃保持旧成功游标，下次重扫但复用已提交步骤。
- 已隔离的坏附件、待分类、缺 JD 项只要完整落库并进入待办，就属于“已登记的单项异常”，允许本批次成功带异常；后续通过独立重试队列处理。
- 邮箱中断导致扫描不完整、写表未完成、数据库不可写等全局错误，不推进成功游标。
- 评估结果和岗位报告可先持久化；总览失败则批次停在待写表。重试只补写，不能重复收费调用模型。

### 4.2 正确的完成状态

| 批次状态 | 含义 | 推进成功游标 |
|---|---|---|
| SUCCESS | 所有目标邮件完成登记，报告已提交 | 是 |
| SUCCESS_WITH_EXCEPTIONS | 报告已提交，单项异常已隔离并建待办 | 是 |
| BLOCKED | 配置、JD 全空、数据库或报告写入受阻 | 否 |
| FAILED_RETRYABLE | 邮箱网络、模型服务等导致批次未完成 | 否 |
| CANCELLED | 用户在安全边界取消 | 否 |

通知失败不会撤销已成功写入的报告和游标；通知独立进入重试队列，界面保留未读告警。

## 5. 邮件、附件和分类规则

### 5.1 邮件过滤

- 仅收件箱 INBOX，且在规定窗口内。
- 不依赖“已读 / 未读”；不标记已读，不移动、不删除邮件。
- 原文“主题包含‘【BOSS直聘】、应聘’关键词”有 AND / OR 歧义。设计暂按同时包含两项，设置页可切换；正式启用前需确认并展示命中样本。
- 支持一封邮件多个 PDF；非 PDF 附件记录跳过，不自动解压或打开其他类型文件。
- 原始 Message-ID 缺失或重复时，仍依靠账号 + 文件夹 + UIDVALIDITY + UID 唯一标识接收事件。

### 5.2 去重的三个层次

1. 按邮件事件身份 + 附件 SHA-256 去重，满足“邮件 ID + 附件哈希”要求。
2. 相同 PDF 被不同邮件投到同一岗位：保留每次来源，只复用同一申请及相同 JD / 规则版本下的评估，避免重复行和重复分析。
3. 同一 PDF 投不同岗位：复用解析文本，建立不同岗位申请，分别评估。文件内容有变化则是新版本，不凭姓名覆盖旧简历。

人员实体关联只能依据用户确认或可信、合规的标识；姓名相同不等于同一候选人。哈希相同也不能用来跨岗位跳过匹配。

### 5.3 PDF 与 OCR

- 同时核对后缀、MIME 和文件签名；设置大小、页数、解析耗时上限。数值须用真实样本调优。
- 下载流写临时文件，完成后计算哈希并登记；解析成功后归档原件，字节内容不变。
- 先逐页提取文本。图像页、混合 PDF 中无有效文字的页才进入本机 OCR；OCR 输出是独立衍生文件。
- 保存页码、文本片段 ID、页面框坐标（可取得时）及 OCR 质量；关键学历、年月等低质量信息标成未知，进入人工复核。
- 加密、损坏、超时或无法解析的附件放入隔离区，保留原因；不尝试破解密码。
- 单个失败不阻止其他独立附件处理；同类大量失败提示可能是解析器系统性故障，打开熔断并停止该阶段。

### 5.4 岗位分类

默认从原始附件文件名提取第一段完整的中文 `【…】`，以内部第一个 `_` 前内容为岗位标识。例如：

```text
【后端研发工程师_候选人甲_5年】.pdf → 后端研发工程师
【销售经理_候选人乙】.pdf           → 销售经理
【产品经理】.pdf                   → 产品经理（无下划线时取整段）
简历.pdf                          → 待分类
【_候选人丙】.pdf                  → 待分类
```

规则来源“命名”暂解释为附件文件名，正式运行前用邮件样本确认。如果岗位只出现在主题中，必须显式启用主题回退，不能默默猜测。

- 岗位标识经已确认的别名表映射到规范岗位，目录以规范岗位名命名。
- 缺括号、空岗位、多段互相冲突、未知岗位进入待分类，不让模型自动建岗位。
- 过滤 Windows 非法字符、保留名和路径穿越；路径解析后必须仍在简历根目录下。
- 归档名称建议 `原文件名主体__哈希前12位.pdf`；冲突时延长哈希或使用唯一 ID，绝不覆盖不同内容。原始名称单独保存。
- 原始字节不变。去标识化文本、OCR 结果、缩略图、分析结果另存，不回写 PDF。

## 6. JD 完整性与结构化

第一期建议支持 PDF、DOCX、TXT；扫描 JD 可走本机 OCR。原始文件、提取文本和已确认结构化内容分别版本化。

“JD 信息完整”需要可执行定义。每个岗位至少包含：岗位身份与销售标志、主要职责、核心技能、经验要求、学历策略、工作地点或明确不限。证书、到岗时间及其他硬条件必须显式填写“要求内容”或“未要求 / 不限”，不能把空白当作不限。

模型从原文提取候选结构；用户可在结构化模板中补足缺失项并批准，补充项形成新的 JD / 规则版本，不能伪称来自原始文件。

| 缺失情况 | 行为 |
|---|---|
| 全局 JD 目录为空 / 没有任何有效 JD | 预检失败，立即提示，不启动新评估 |
| 某岗位没有 JD | 可保留原件和候选人，状态“待 JD”，不生成分数和等级 |
| JD 有关键缺失项 | 标注具体“JD 缺失项”，停止该岗位评估 |
| JD 存在多个未指定当前版的文件 | 要求选定当前版本，不随机选择 |
| 部分岗位正常、部分 JD 不完整 | 正常岗位继续；异常岗位出现在汇总待办 |

“待 JD / 待分类 / 待解析”属于未评估，不能写成 0 分或“不推荐”。

## 7. 评分设计

### 7.1 分数和等级

| 维度 | 上限 | 评价对象 |
|---|---:|---|
| 硬性条件 | 20 | JD 中学历、相关年限、证书、地点、到岗等明确要求 |
| 核心技能 | 30 | 技能、工具、技术栈及实际使用深度 |
| 工作经验 | 30 | 行业、相关职责、项目复杂度、明确要求的组织经验 |
| 项目成果 | 10 | 量化结果、本人贡献、主导职责 |
| 稳定性 | 10 | 可核验的任职区间及换岗记录 |

总分是五项之和，称“匹配度 /100”，不是录用成功概率。模型置信度和证据完整度另列，不能混入匹配度。

每个维度由事先确认的细则拆成若干条目；同维度分值合计等于其上限。程序根据“满足、部分满足、不满足、未知”及细则映射分数；模型只能提取证据和提出判定。

初始细则建议：满足计该条目全分，部分满足计约定分档，不满足计 0，未知暂不授分并显示缺证据。具体分档和硬条件条目权重由 JD 确认，不能由模型每次自由变化。未知导致的是暂计分，不代表事实不符合；关键条件未知或一般条目未复核时，最高建议“待定”。

- 85–100：强烈推荐。
- 70–84：推荐。
- 60–69：待定。
- 0–59：不推荐。
- 任一硬条件明确失败：建议等级上限为“待定”；总分低于 60 仍为“不推荐”。显示触发的具体条件。
- 硬条件未知：标“待核验”，建议等级最多“待定”；不把未知写成明确失败。
- JD 不完整、岗位未定、解析或模型输出不可靠：没有有效分数和等级。
- 人工复核可以记录不同意见；不篡改原始分数、证据及历史建议。无自动拒信或自动淘汰。

### 7.2 学历规则的实现

保留用户提出的筛选口径并做成版本化配置：

| 情况 | 初始处理 |
|---|---|
| 销售岗位 | 免于全局本科院校门槛；仍按该岗位 JD 的其他条件评估 |
| 非销售，本科为所依据学历 | 须有统招证据，且院校属于经确认的 985 或 211 名录 |
| 非销售，硕士 | 放宽学校要求；仍核验学历层级及 JD 明确条件 |
| 统招 / 院校 / 学位完成情况不清楚 | 待核验，不能凭学校名或“全日制”自动推断统招 |
| 博士、境外学历、在读、非全日制硕士、专升本等未明示口径 | 待人工确认规则后处理，不能自行决定通过或拒绝 |

院校名录须使用经确认、可追溯的版本，含学校曾用名映射；不让模型自由凭记忆判断。原需求尚未明确“取得硕士后是否仍追溯本科院校”等情况，应在上线前确定。

### 7.3 年限、成果与稳定性

- 年限至少区分总工作年限、相关岗位年限；按月份合并重叠区间，不能简单累加兼任经历。
- 任职日期截至本次评估日；缺月、重叠、自由职业、实习、内部调动须独立标注。
- 只引用简历明确给出的成果和本人角色；公司名气不等于项目复杂度，不能推测公司规模。
- 稳定性先输出中性的日期事实和跳转次数，再按岗位批准的细则计分。短项目合同、内部转岗、并购等有证据的情况单列；无原因记录不能猜测离职动机。
- 不根据性别、年龄、民族、婚育、健康、宗教、照片等内容评分；经历空档不推断家庭或健康原因。

### 7.4 每项结论的证据结构

```text
要求：有关系型数据库性能优化经验
JD 依据：JD-v3，第 1 页，J-07
简历依据：R-12，第 2 页，“负责订单查询索引调整，耗时由 1.8 秒降至 0.5 秒”
判定：满足；尚未核验指标的真实性
评分：技能条目 S-02，6 / 6
面试建议：追问数据量、指标测量方式与候选人实际贡献
```

这里是格式示例，不是现实候选人的事实。实际报告中的每段引文都必须能匹配保留的来源文本，跨文档引用、找不到原文或页码不符均不能通过自动校验。

### 8.1 总览可见列保持原有 15 项

| 列名 | 权威来源 / 写入者 | 说明 |
|---|---|---|
| 岗位名称 | 程序 | 使用确认后的规范名称 |
| 推荐日期 | 程序 | 初次有效推荐日期；未评估时留空，后续重新评估记录在详情 |
| 姓名 | 程序 | 简历有明确姓名时填；未知留空，不根据邮箱猜 |
| 匹配度 | 程序 | 0–100；未评估为空 |
| 推荐等级 | 程序 | 四档；未评估为空，原因写在建议 |
| 当前公司 | 程序 | 原文事实，未知留空 |
| 年限 | 程序 | 明确单位和计算口径，如总年限；相关年限在详情 |
| 核心优势 | 程序 | 简短结论附证据编号 |
| 主要风险 | 程序 | 区分不符合与尚待核验，附证据编号 |
| 建议 | 程序 | 待确认项、面试追问、报告链接 / 证据编号 |

设计增加一列隐藏内部 ID `_application_id`，不改变这 15 项可见结构。不能按行号、姓名或排序位置回填。保护 ID 只用于防误操作，不是访问控制。

### 8.2 更新策略

1. 读取现有工作簿及文件指纹，检查模板版本、表头、ID 唯一性。
2. 按申请 ID 收集五字段的原始值、数据类型、公式及必要样式，保存同步快照。
3. 合并新申请 / 已确认重评的机器字段；旧行五字段一律带回原值，新行五字段留空。
4. 按推荐日期降序、岗位名称升序排序，同键用申请 ID 保证稳定；未评估空日期放在最后。原文未指定升降序，此处作为默认，可调整。
5. 在同目录输出临时工作簿，验证所有老行五字段逐项不变、新行 ID 唯一、行数和类型正确，再重新检查源文件未变化并尝试安全提交。
6. 工作簿被 Excel 占用、源文件变化或存在 ID / 内容冲突时不覆盖，保留待合并版本和待办，用户关闭 / 解决后重试。

对已有手工报表的首次导入，生成行匹配预览，无法唯一匹配的行人工关联后才能更新。对手工删除的行、重复复制的 ID、被改写的机器字段分别提示，不自行推断删除意图。

标准输入为本软件生成的 `.xlsx`。遇到宏、合并复杂模板、外链、复杂图表等先判断兼容性，不能用通用库打开后静默丢失内容。人工公式保留为公式，不执行；下次 Excel 打开后可能重新计算，不能承诺缓存值永远相同。

### 8.3 单岗位推荐报告

推荐第一期生成可离线打开的 HTML，避免为每份报告引入 Word 自动化。路径：`推荐\YYYY-MM-DD\岗位名称__批次ID.html`。

包含岗位和 JD / 规则版本、批次覆盖范围、候选人分组、五维得分、硬条件、优势、风险、追问建议、简历与 JD 来源链接及具体引文。HTML 中只呈现经转义的数据，不执行模型生成的脚本。

没有有效评估的岗位只生成异常 / 待办说明，不伪造推荐报告。历史岗位报告不覆盖，主总览持续更新。

## 9. 反馈如何改进推荐

“不断优化”实现为一个受控闭环：收集人工反馈 → 分析偏差 → 提出规则草案 → 回放比较 → 用户批准 → 新版本生效。

1. 从 Excel 同步“部门筛选结果”和“面试评价”；同时使用已有面试日期 / 当前状态判断流程阶段。空白意味着暂无反馈，不能记为失败。
2. 自由文本在本机保留。模型可将评价整理为“技能深度 / 经验 / 沟通 / 其他”，但只有有来源的业务理由能进入调整建议；主观或不相关理由排除。
3. 按岗位和规则版本区分数据，不混合销售与研发。展示样本量、观察周期、结果未回填数量和选择偏差。
4. 先做规则调整建议，例如某条“关键词出现”过于宽松，建议改为“项目中明确使用并有责任证据”。不直接把用人部门偏好变成全局事实。
5. 可比较有反馈样本的 Precision@K、推荐组筛选通过率等。未推荐者往往没有面试结果，因此不能无条件声称总体召回率或准确率提高。
6. 使用时间切分的历史回放，保证只用当时可用简历和 JD，防止把后续面试结果当作原始特征。每个岗位样本不足时只展示观察，不自动调参。
7. 候选人信息不用于训练 / 微调模型。第一期只调整本机规则、词表、条目分值或提示模板；每次变更需用户批准，保留前后版本与回滚。
8. 院校 / 学历等全局硬条件、五维总权重和等级阈值未经明确批准不得由反馈学习自动放宽。被保护属性及其替代特征不参与学习。

## 10. 通知、异常与日志

默认通过工作台通知中心和 Windows 本机通知提示用户；Windows 通知不含姓名、联系方式和简历内容。SMTP、企业微信、钉钉等对外通道不在第一期默认启用，后续须明确接收人和内容授权。

完成通知至少包含：新增简历数、归档数、各岗位数量、四档人数、未评估数、报告路径、异常摘要。通知点击进入批次详情。

一句话模板：**本次处理 X 封邮件，新增 X 份简历，生成 X 份岗位推荐报告，异常 X 条。**

统计口径：处理邮件 = 主题命中且已登记处理的邮件；新增简历 = 本批次首次成功解析的唯一原件；多岗位申请另计；新下载但解析失败仅算新增附件。新增岗位投递与新增原件分开展示。等级人数 = 本批次有效评估的申请数；同一人多岗位会有多条申请，应明确标注。异常条数 = 去重后的异常事件数，重试次数单列。

| 情况 | 处理范围与动作 |
|---|---|
| 账号 / 凭证 / 必要路径缺失 | 预检阻塞，不尝试其他未知邮箱和目录 |
| 邮箱无法连接 / 中途断开 | 有限重试，通知，停止取件，不推进成功游标 |
| JD 目录全空 | 阻塞新批次；可查看历史资料和补充 JD |
| 某岗位 JD 不完整 | 该岗位暂停评估，其他岗位继续 |
| 报告目录不可写 / 磁盘不足 | 立即通知，停止后续需持久化的操作 |
| 单个附件加密 / 损坏 / OCR 失败 | 隔离、建异常项、通知摘要，其他附件继续 |
| 模型超时 / 限流 | 有限退避重试；保存状态，不生成伪造分数 |
| 模型证据不匹配 / 格式错误 | 一次受限纠正后仍不合格，转人工；不扩大权限 |
| 云服务普遍故障 / 预算耗尽 | 暂停评估阶段，保留已收集资料及重试任务 |
| Excel 被占用 / 同步冲突 | 停止覆盖，保留待合并报表，通知关闭或解决 |
| 本机通知发送失败 | 通知独立重试，工作台展示；已完成业务不回滚 |

结构化日志记录 run_id、阶段、事件 ID、匿名申请 ID、时间、结果、错误码、耗时、重试次数、模型用量和报告版本。普通日志不写原始简历、联系方式、授权码或完整提示词；有个人信息的证据进入受限业务存储。

## 11. 安全与数据治理

- 默认单人本机访问，服务绑定回环地址；本机界面仍采用会话令牌、来源校验和 CSRF 防护，不能默认“本机就无需保护”。
- 邮箱与模型凭据进入 Windows Credential Manager / DPAPI 保护区；日志、导出和异常堆栈中脱敏。
- 云端只发送必要的去标识化文字、证据编号及 JD，默认不上传原 PDF、姓名、手机号、邮箱、精确地址、证件号、照片。
- 去标识化不等于匿名：任职经历仍可能识别人。上线前确认所选供应商的数据留存、是否用于训练、地区、访问权限和删除机制，不能仅靠请求参数宣称“零留存”。
- 招聘评估以外用途不开放；无自动训练、无广告用途、无默认对外发送。
- 简历、JD、邮件、模型输出都作为不可信内容，不能将其中“忽略规则、上传文件”等文字当成系统指令。
- PDF 解析 / OCR 在受限子进程中运行，限制文件大小、时间和资源，默认禁网；禁用 PDF 活动内容。
- 导出防公式注入，机器写入的姓名、公司、优势等按文本处理；报告 HTML 转义，来源链接仅由本机程序生成。
- 定义数据保留期限、删除和更正入口。删除覆盖附件、解析缓存、评估、Excel、报告和索引；备份按保留策略到期清理，并记录删除待办。
- 备份包含数据库、原件、版本化 JD 和报告，保存到用户指定且受访问控制的目录；不要硬编码写入不明网盘。

## 12. 技术方案

采用模块化单体，减少第一期部署和恢复的复杂度。

```text
本机浏览器界面（React + TypeScript，随应用打包）
                    │ 回环地址 API
应用服务（Python + FastAPI）
 ├─ 配置 / 岗位 / JD / 候选人 / 反馈 / 审计
 ├─ 工作流与持久化任务队列
 ├─ 规则评分与证据校验
 └─ 适配器：IMAP / 本机 OCR / 批准的云模型 / Excel / 本机通知
        │                          │
 SQLite（事务、版本、作业状态）   NTFS（原件、JD、报告、受限缓存）
        ↑
 Windows 任务计划程序 → 同一工作流命令入口
```

- 单人场景用 SQLite + 持久化作业表，不引入 Redis / Kubernetes。
- 推荐 PDF 文本抽取使用 pypdf / pdfplumber，OCR 采用可打包的本机引擎；实际选型需以中文简历样本、精度和许可证检查为准。
- `.docx` JD 用 python-docx 读正文与表格；标准 `.xlsx` 用 openpyxl，在支持范围内做受控合并。
- 模型经统一适配器接入，要求结构化输出、超时与用量记录；更换模型必须过同一证据和评分验证。
- 发布形式为 Windows 可执行应用 / 安装包，内含服务、前端和所需运行时；启动后打开本机工作台。
- 定时工作与界面生命周期分离。关闭浏览器不影响已安装的调度；电脑关机或断网时不承诺 09:00 准点完成，恢复后补跑并展示实际时间。
- 初版计划任务使用当前用户身份，凭据读取与实际运行账户一致。是否支持退出登录后运行需在部署时单独验证。
- 将来多人使用再迁移 PostgreSQL、角色权限和内网服务；不在本期加入多人冲突协作。
